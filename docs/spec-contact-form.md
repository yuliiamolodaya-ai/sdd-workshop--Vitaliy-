## 1. Постановка проблеми

**Кого** це стосується?  
Відвідувачі публічного сайту (контакти, співпраця), які надсилають звернення; співробітники фундації, які отримують сповіщення; контекст вікна нотаток (та сама форма — див. Q-11, Q-29).

**Який** біль чи можливість?  
За issue #2 форму потрібно «посилити»: **обов’язковий телефон**, можливість **додати документ (CV або портфоліо)** у листі звернення, **сповіщення з новим полем**. Зараз телефон можна не вказувати, файлу немає, лист-сповіщення команді фактично не надсилається (заглушка).

**Чому зараз** (тригер, метрика, ризик)?  
Тригер: issue #2. Цілі, метрики успіху та обмеження приватності/зберігання замовник **не називав** (`contact-form-feature.md`, §2). Ризики розриву макет ↔ сайт і copy ↔ `i18n` — `figma-contact-form-analysis.md` (B-01…B-06).

**Бажаний результат (одне речення):**  
Відвідувач надсилає звернення з обов’язковим телефоном і за потреби з необов’язковим PDF (узгоджений тип і розмір — Q-03); команда отримує сповіщення з телефоном і, якщо файл додано, з цим файлом (посилання або вкладення — Q-09).

## 3. Актори й потік

| Актор | Опис |
| --- | --- |
| Відвідувач сайту | Заповнює контактну форму (uk/en), надсилає звернення |
| Співробітник фундації | Отримує сповіщення про звернення (ціль — з телефоном і опційним файлом) |
| Форма (клієнт) | Валідація, відображення помилок мовою сторінки, відправка звернення |
| Сервер / перевірка | Серверна валідація; помилки сервера англійською (RULE-14) |

**Основний потік (щасливий шлях):**

```text
1. Відвідувач відкриває форму (контакти, співпраця або нотатки — Q-11/Q-29).
2. Заповнює ім’я, email, обов’язковий телефон, повідомлення; за бажанням — PDF; вмикає згоду.
3. Форма нормалізує телефон («+» і цифри), за потреби показує прогрес відправки (макет «Надсилання» — Q-24, Q-30).
4. Звернення приймається; відвідувач бачить підтвердження (макет: inline success — Q-15; зараз: модалка).
5. Формується сповіщення з телефоном і, якщо був файл, з файлом (посилання або завантаження — Q-09, AC-05).
```

**Альтернативні / винятки:**

- Порожній або невалідний телефон — помилка біля поля (AC-01, AC-03, AC-11); макет «Хибний телефон» (Q-05, Q-17).
- Файл > 5 МБ або не PDF — не приймається (AC-06, AC-07); макети «Завеликий файл», «Не PDF».
- Згода не відмічена — відправка не викликається (AC-09, RULE-10).
- Помилка після submit — макет: алерт + retry, поля збережені (Q-25; зараз RULE-15, Q-07).
- Вікно нотаток: submit без запиту на сервер, перехід до підтвердження (`contact-form-feature.md` §4) — Q-40.
